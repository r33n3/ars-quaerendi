# Using the skills together

The package provides agent meta skills for choosing methods, assessing evidence and deciding how to proceed. Regular task skills perform specific work such as extracting records, calculating figures or executing tests. One or more agents can apply both kinds during a task. See [meta skills and task skills](meta-skills.md) for the distinction.

## Control of the work

The person or host agent controls the purpose, execution, permissions and collaboration. Each participant checks its own permissions and the evidence received from others.

## Choosing skills

Choose a skill according to the work at hand:

* Use `purpose-planning` to choose goals and plan work.
* Use `inquiry` to answer unfamiliar questions.
* Use `toolcraft` to find, adapt or build a tool.
* Use `judgment` to assess the evidence for a decision.
* Use `discovery` to investigate unexpected observations.
* Use `contribution` to preserve useful results.
* Use `reliability-by-construction` to prepare a prototype for repeated use or deployment.
* Use `performance-metric-integrity` to check reported results and evaluate proposed improvements.
* Use `institutional-intelligence` to assess negotiations, disputed claims, incentives and outside pressure to change goals.

Combine skills as needed. Record the reason for using each one and keep the work within the user's purpose.

## Uses across tasks

An agent or several agents can use the skills to investigate claims, assess evidence, diagnose failures, develop helpers, plan work and test recovery. Other uses include reviewing recurring incidents, checking reported measures, assessing supplier promises, preserving reusable methods and examining meeting comments.

See [agent examples](agent-examples.md) for task material, suggested skills, expected results and example requests. Choose skills for each part of the task. One agent may apply several methods, or authorized collaborators may divide the work. The host supplies tools, access and execution controls.

## Meeting note taking agents

Use the skills to examine meeting comments, commitments, disputed claims and recurring behaviors in supplied notes. Include speaker labels and source locations in findings, and keep observations separate from tentative interpretations. See the [meeting review guide](meeting-notes.md) for selection, expected inputs and a result format.

## From experiments to deployment

1. Explore the question through small experiments. Record findings, failures and promising leads.
2. Build a prototype and check its behavior with repeatable tests.
3. Run a limited trial under realistic conditions. Test permissions and recovery from relevant failures.
4. Assess readiness for the intended version, environment and use. The user and host environment authorize deployment.
5. Track results, reliability, costs and other measures that could reveal problems. Check reports against the original records.
6. Use the evidence to propose improvements. Preserve earlier definitions, findings and failed attempts so comparisons remain meaningful.

Choose the amount of testing according to the consequences of failure. Record reported progress and independently verified progress separately. Assess an agent's performance through source records and independent checks.

## Negotiations and disputed claims

Start with the user's purpose and existing permissions. Identify the offer or claim, supporting evidence, interests, costs and possible consequences. Use other skills when a specific question needs research or checking. Propose a response with clear limits and identify any authorization needed for commitments, access or changes to goals. Keep a record of the evidence and options available when the decision was made.

For difficult decisions about collaborators, promises, shared sources, accountability or continued investment, consult [further negotiation methods](../references/institutional-resilience-advanced.md). Apply the parts relevant to the decision.

## Guided research practice

When requested, an agent can practice investigation through a challenge with clear limits, recorded evidence and separate evaluation criteria. Use explanation review to document how a result was obtained and test a proposed transfer on another task. See [guided research practice](../references/research-apprenticeship.md).
