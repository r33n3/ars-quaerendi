# Examples of purpose and goal review

These scenarios and their records are invented. They demonstrate proposal structure. Actual evidence, authorization and execution results need to be supplied in a real task.

## Consider a new investigation

The user wants an accurate and dependable scheduled import. A review raises the possibility that repeated delivery creates duplicate records. The records supplied so far leave that behavior unresolved.

Agents can use Purpose Planning to propose an investigation, compare existing checks and collaboration with building a helper, and record the costs and resource limits. The opportunity is a hypothesis. Actual authorization is unknown in this example.

The [goal proposal](purpose-to-action-goal.json) records a hypothetical investigation with an example budget. Before acting, apply the actual user's authorization and resource limits. Compare completed tests with the baseline and preserve any useful tests or findings even if the proposed improvement proves unnecessary.

## Continue with current goals

The user has already agreed a report and priorities. A review raises an optional extension, while the available evidence provides little reason to add it now.

The [current goals record](purpose-to-action-no-goal.json) recommends continuing the existing plan. Its goal and success criterion are null because the review proposes keeping current goals. Reconsider the extension if the user changes priorities or new evidence shows a material gap.

## Using the result

Judgment can assess the evidence and recommendation. Inquiry can investigate open questions. Toolcraft can review a demonstrated gap. Contribution can preserve useful results. Each receives the relevant evidence, limits and authorization context.
