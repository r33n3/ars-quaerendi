# Designing experimental environments

Use this method when existing observations leave competing mechanisms unresolved and a limited intervention could distinguish them. A proposed design can still be useful when execution is unavailable.

1. Specify the models and each model's predictions under changed conditions.
2. Identify variables to change, variables to hold constant, environmental conditions, instruments and possible confounders.
3. Choose the smallest useful intervention with a baseline. Consider factorial designs, sensitivity checks, stress tests, negative controls or counterfactual comparisons when they answer the question.
4. Check measurement validity through calibration, detection thresholds, sampling, instrument effects, coverage and reproducibility.
5. Record the authorized operating boundary and resource budget. Use isolation where appropriate. Physical experiments, production changes, external actions and added resources follow the user and host's actual authorization.
6. Record the test as proposed, executed, failed or stopped. For execution, preserve raw and derived results, versions, seeds, conditions and evidence identifiers. Compare recorded predictions with observations.
7. If a discriminating test is infeasible, return an underdetermined result and the reason. Preserve the candidate models.
8. Stop at the agreed budget, sufficient discrimination, an instruction to stop or unsuitable experimental conditions.

## Optional exploratory branch

Use unusual environments or alternative assumptions when the user requests exploration or an approved evaluation includes it. Label each design as a thought experiment, simulation, software test or physical experiment. Record its operational definitions, predicted observations and potential falsifiers.

A thought experiment produces reasoning and predictions. An executed simulation produces results about its simulated conditions. Physical and software claims require observations in their respective domains. Retain the domain and limits when transferring a result.

## Output and consumers

Return an experiment identifier, candidate models, predicted signatures, controls, operating limits, resource budget, authorization context, execution status, input evidence and residual uncertainty. Include result evidence only for work actually performed. Keep a proposed experiment separate from observed evidence.

Inquiry can use the results to revise models. Judgment can assess support. Discovery can examine unexpected results. Reliability by Construction can assess repeated use within the tested conditions.
