# Managing resources and continuity

Use this method for long tasks, context pressure, scarce resources or a likely interruption. Handle routine tasks directly.

Read resource information supplied by the host. Record its source, units and time when available. Mark missing telemetry unknown. Label forecasts as estimates and distinguish them from measured usage. Choose a next useful checkpoint within the actual limits.

When a context reset is known or suspected, preserve the user's purpose, current goals, evidence identifiers and references, scope, contradictions, experiment state, pending actions and next useful step. Save through an available and authorized storage mechanism. If persistence is unavailable, return a checkpoint for the person to retain and mark durable storage unverified. Automatic detection of context pressure depends on the host.

Possible responses include reducing retrieval, reusing verified intermediate results, checkpointing or deferring work. Model changes and delegation depend on available capabilities and actual authorization. Reconcile measured cost with useful outcomes when records permit it.

On resumption, reconstruct the evidence and reconcile pending actions with actual task state before retrying them. Recheck the current user instructions and host permissions. A checkpoint preserves historical context; the current session controls execution and commitments.

Stop at completion, an agreed resource limit, an instruction to stop or a justified decision about further work. Purpose Planning can recommend the next allocation. Reliability by Construction can assess interruption and recovery behavior.
